# 릴스 자동 제작 — 예약 실행이 읽고 그대로 하는 문서

사용자 결정(2026-11-26):
- "앞으로 릴스를 생성해서 텔레로 보내면 내가 피드백해서 올리는 걸로."
- "예정된 릴스는 다 일정으로 잡아서 그 시간에 시작되도록, 놓쳐서 못 올리는 일 없게."

그래서 흐름은 이렇다.
1. 정해진 시각에 제작을 시작한다.
2. 큐에 넣으면 텔레그램으로 미리보기와 한국어 줄거리가 간다.
3. 사용자가 답장으로 피드백하면 고쳐서 같은 슬롯에 다시 넣는다.
4. **답이 없으면 예정대로 올라간다**(놓치지 않는 게 먼저).

## 누가 이 문서를 부르나

- **데스크 앱 예약 작업 「릴스 자동 제작」 — 매일 13:00(한국).** 72시간 안에 다가온 빈 슬롯이 있으면 하나를 맡는다.
  - 월 슬롯(한국 화 09:00)은 토 13:00에, 수 슬롯은 월 13:00에, 금 슬롯은 수 13:00에 시작한다. 그다음 날 13:00은 다시 시도하는 기회다.
- **대비 실행: `reel_queue.py run`(launchd, 10분마다).** 데스크 앱이 꺼져 있어 게시 30시간 전에도 비어 있고 아무도 만들고 있지 않으면 `claude -p` 로 이 문서를 직접 실행한다. 프롬프트에 대상 슬롯이 적혀 온다.
- **누군가 대신 만들어 달라고 할 때** — 텔레그램 「다음 릴스 만들어줘」 등.

## 어디서

작업 폴더 `WT=~/.local/share/withgod-ig-reels/repo`에서 한다. 자동 제작 전용 git 워크트리이고 브랜치는 `feat/ig-reels-auto`다. 데스크 앱이 정리하지 않는 곳에 두었다.

- 모든 명령은 이 폴더 기준이다(절대 경로로).
- `Q="python3 $WT/backend/instagram/reels/reel_queue.py"`.
- 그림·중간 파일은 `~/.local/share/withgod-ig-reels/work/<slug>/`에 둔다.

텔레그램에는 두 가지만 간다.
1. `add`가 보내는 미리보기.
2. 문제(막힘·실패) — `$Q`의 알림이나 `~/WithGod/scripts/tg-notify.sh`로.

진행 상황("시작합니다", "그림 그리는 중")은 보내지 않는다(전역 CLAUDE.md, 11/25).

## 1. 준비와 슬롯 맡기

1. 저장소를 맞춘다.
   - `cd $WT && git fetch -q origin && git status --short`.
   - 앞 실행이 남긴 변경이 있으면 무엇인지 보고, 편 원본이면 커밋한다.
   - `git pull --ff-only`(업스트림이 있을 때).
2. 슬롯을 맡는다.
   - 프롬프트에 슬롯이 주어졌으면 그 슬롯을 만든다. launchd가 이미 「제작 중」으로 표시했다.
   - 아니면 `$Q next --claim --by "데스크 예약"`을 부른다.
     - 결과가 `{"slot": null}`이면 할 일이 없다. **아무것도 보내지 말고 끝낸다**(매일 도는 실행이니 조용해야 한다).
     - 결과의 `format`·`topic`·`note`가 편성표의 주제다.
   - 편성표에 주제가 없으면(12/30 뒤) README 「형식」 규칙과 지난 편들을 보고 주제를 고른다. 그 주제를 `lineup.json`에 적고, story.md 맨 위에 "주제는 자동으로 골랐습니다" 한 줄을 둔다(미리보기에 같이 간다).

## 2. 만들기 — 사람이 만들 때와 똑같이

[.claude/skills/withgod-reel/SKILL.md](../../../.claude/skills/withgod-reel/SKILL.md)의 순서를 그대로 따른다. 그 전에 README.md·REVIEW.md를 처음부터 끝까지 읽는다.

1. **메시지 한 줄 → `story.md`.** 사실은 원래 기록으로 확인한다. 찬송가·인물 일화는 부풀려진 판이 많으니 사실 확인을 서브에이전트에 맡긴다(본보기: 찬송가 편).
2. **새 서브에이전트에게 블라인드 검토를 맡긴다**(REVIEW.md 「검토자에게 줄 말」).
   - [막음]이 있으면 고치고, 매번 새 검토자로 다시 검토한다.
   - 3회 안에 통과 못 하면 막힌 점을 텔레그램으로 묻는다. 그다음 `$Q release <slot>`을 부르고 끝낸다.
3. **그림 → 음악 → spec → `finish.py`.** 스냅을 한 장으로 붙여 REVIEW 「화면」 항목과 S4(어두운 구간·밝아지는 순간)를 직접 본다.
4. **본보기:**
   - 인물 이야기 `episodes/martha`
   - 찬송가 `episodes/now-thank-we` — 바흐 코랄을 music21로, 가사를 그 줄 선율에 맞춤
   - 성화 `episodes/prodigal` — 액자 + 내레이션
   - 수요일 Mia `episodes/thanksgiving` — 앱 녹화는 README 「앱 시연」대로 시뮬레이터
5. **시간 예산은 3시간 안쪽이다.** 4시간이 지나면 「제작 중」이 풀려 다른 실행이 같은 슬롯을 다시 맡을 수 있다. 오래 걸리면 `$Q next --claim`을 다시 부르지 말고 그대로 끝까지 간다.

## 3. 큐에 넣고 남기기

1. `caption.txt`·`story.md`를 작업 폴더에도 둔다.
2. `$Q add <작업폴더> --slot <slot> --format <format> --title "<한국어 이름>"`을 부른다.
   - 텔레그램으로 미리보기 영상, 한국어 줄거리, "고칠 점은 답장으로" 안내가 간다.
   - 이것이 사용자에게 가는 알림이다.
3. WT에서 `episodes/<slug>/`, 편성표 메모, `docs/STATUS.md` 「올린 편·큐」 한 줄을 커밋하고 push한다.
   - PR이 없으면 `gh pr create --base app-develop`(제목 "feat(instagram): 릴스 자동 제작분").
   - 커밋·PR 본문에 Claude 서명 줄을 넣지 않는다.
4. 도중에 그만두면 `$Q release <slot>`을 부르고, 무엇이 막혔는지 텔레그램으로 한 통 보낸다(문제 알림).

## 피드백이 오면(텔레그램 답장)

텔레그램 브릿지는 가장 최근에 끝난 세션을 이어받는다. 이어받은 세션이 이 편을 만든 세션이 아니어도 이 문서대로 처리한다.

1. **어느 편인지 찾는다.** 답장이 가리키는 편이고, 모르면 `$Q status`에서 가장 가까운 대기 편이다. 편 원본은 `$WT/backend/instagram/reels/episodes/<slug>/`, 작업 폴더는 `~/.local/share/withgod-ig-reels/work/<slug>/`에 있다.
2. **고치기 전에 지적을 먼저 적는다.** REVIEW.md 체크리스트와 「사용자가 지적한 것」 표에 한 줄 더한다(스킬 규칙 — 같은 지적을 두 번 받지 않게). 형식 자체가 바뀌는 지적이면 README 「형식별 메모」에도 적는다.
3. **고친다.** 대본을 바꿨으면 새 검토자에게 다시 맡긴다. 그다음 `finish.py`를 다시 돌린다.
4. **다시 넣는다.** `$Q add <작업폴더> --slot <그 슬롯> --replace --format <format> --title "<이름>"`을 부르면 「고친 편으로 바꿔 넣음」 미리보기가 간다.
   - 이미 올라간 편이면 바꿀 수 없다고 답한다.
5. 커밋·push 한다.
6. **사용자가 "올리지 마"라고 하면** 큐 폴더 `~/.local/share/withgod-ig-reels/queue/<날짜>-<slug>`를 `queue/replaced/`로 옮긴다(취소). 그리고 그 슬롯을 다시 만들지 물어본다.

## 점검

- `$Q status` — 슬롯마다 ✅ 대기 · 🛠 제작 중(언제부터, 누가) · ⬜ 비어 있음.
- `$Q auto-check` — 대비 실행이 지금 무엇을 띄울지 미리 본다.
- 대비 실행 로그는 `~/Library/Logs/withgod-ig-reel-make.log`, 큐 로그는 `~/Library/Logs/withgod-ig-reel.log`.
- 게시 24시간 전에도 비어 있고 아무도 만들고 있지 않으면 텔레그램 「📭 다음 릴스가 아직 없습니다」가 간다. 이 알림이 오면 자동 제작이 실패한 것이다.
