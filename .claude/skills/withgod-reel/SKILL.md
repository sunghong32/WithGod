# WithGod 릴스 만들기

사용자 바람(2026-11-20): "완전 자동으로, 내가 피드백하지 않아도 알아서 잘." 그동안 편마다 3~5번 고쳤다.
목표는 **사용자가 처음 받아 보는 미리보기가 이미 통과작**인 것 — 사용자는 좋다/아니다만 정한다.

## 순서

1. `backend/instagram/reels/README.md` 를 처음부터 끝까지 읽는다(형식·첫 3초·사용자 피드백 규칙·형식별 메모·캡션).
   `python3 backend/instagram/reels/reel_queue.py status` 로 슬롯과 편성표 주제를 본다.
   만드는 중 진행 상황은 텔레그램으로 알리지 않는다(문제·예약 알림만 — CLAUDE.md).
2. **메시지 한 줄부터.** 「그래서 하나님은 어떤 분인가」에 답하는 한 문장을 못 쓰면 대본을 쓰지 않는다.
   `episodes/<slug>/story.md` 를 [REVIEW.md](../../../backend/instagram/reels/REVIEW.md) 의 틀대로 쓴다
   (메시지 · 누구에게 · 한국어 줄거리 · 대본[화면 + 영어 + 우리말]). 사실은 원래 기록, 성경은 WEB(`backend/data/langs/en/verses.csv`).
3. **검토 — 내가 아니라 새 서브에이전트가.** Agent 도구로 일반 에이전트를 띄우고 REVIEW.md 「검토자에게 줄 말」과 파일 경로만 준다
   (내 의도·변명은 주지 않는다). [막음]이 있으면 고치고 **또 새 검토자**로([다듬기]는 싸면 고친다). 3번 안에 못 넘으면 막힌 점을 텔레그램으로 사용자에게 묻는다.
   통과하면 story.md 머리에 `검토: 통과 — <날짜> <몇 회째>` 를 적는다(`reel_queue.py add` 가 이 줄 없으면 거절).
4. 그림·음악·spec·렌더링은 README 「만드는 순서」 4~7. 렌더링 뒤 스냅을 한 장으로 붙여 REVIEW.md 「화면」 항목으로 직접 본다.
5. `caption.txt`(README 「캡션」), story.md·caption.txt 를 작업 폴더에도 두고 `reel_queue.py add <작업폴더> --title …` —
   텔레그램으로 영상 + 한국어 줄거리가 간다.
6. `episodes/<slug>/` 를 커밋(브랜치 → PR, 기본 브랜치 아님), `docs/STATUS.md` 「올린 편·큐」 갱신.

## 사용자가 고쳐 달라고 하면

고치기 **전에** 그 지적을 REVIEW.md 체크리스트(항목 + 「사용자가 지적한 것」 표)에 한 줄 더한다 — 같은 지적을 두 번 받지 않게.
형식 자체가 바뀌면 README 「형식별 메모」도. 그다음 고친 대본을 다시 새 검토자에게.
